## 0. 基础名词速查表（小白必读）

> 在看后面的章节之前，先搞懂这些反复出现的"缩写黑话"。

### 0.1 芯片与引脚相关

| 名词 | 全称 | 通俗解释 |
|------|------|----------|
| **STM32F103C8T6** | — | 这颗芯片的型号。STM32 = ST 公司的 32 位微控制器，F1 = 产品系列，03 = 子系列，C8 = 64KB Flash，T6 = LQFP48 封装 |
| **GPIO** | General Purpose Input/Output | 通用输入输出口，就是芯片上可以读/写高低电平的引脚。你可以把它理解成"可以开关的电灯开关" |
| **GPIOA / GPIOB / GPIOC** | GPIO Port A/B/C | STM32 把引脚按"端口"分组，每组 16 个引脚（Pin 0~15）。**GPIOA 就是 A 组引脚**，组内的 PA0、PA1...PA15 是这条组里的第 0~15 号引脚 |
| **PA0 / PB3 / PC13** | Port A Pin 0 | "P" = Port（端口），"A/B/C" = 哪一组，"数字" = 该组内第几号引脚。所以 **PA0 = A 组第 0 号引脚**，PB3 = B 组第 3 号引脚 |
| **AF (Alternate Function)** | 复用功能 | 一个引脚不仅能当普通 GPIO 用，还能"兼职"做定时器 PWM、串口、SPI 等专用功能，这叫"复用"。由芯片硬件决定哪个引脚能复用成什么功能 |
| **AF_PP** | Alternate Function Push-Pull | "复用 + 推挽"模式。推挽 = 能主动输出高/低电平；复用 = 引脚交给外设（如定时器）控制，而不是由你手动写代码控制 |
| **Push-Pull (推挽)** | — | 一种输出电路结构，能主动把引脚拉到高电平（3.3V）或低电平（0V），就像一个"双向开关"。与之相对的是"开漏 Open-Drain"，只能拉低，不能拉高 |
| **Pull-Up / Pull-Down** | 上拉 / 下拉 | 芯片内部自带的上拉/下拉电阻。上拉 = 引脚悬空时默认为高电平；下拉 = 默认为低电平。防止引脚"飘着"读到随机值 |
| **EXTI** | External Interrupt | 外部中断。当某个引脚的电平发生变化（上升/下降/任意），可以触发中断通知 CPU。用于检测按键、传感器信号等 |
| **NVIC** | Nested Vectored Interrupt Controller | 嵌套向量中断控制器。STM32 内核中管理所有中断的"调度员"，决定哪个中断先响应、能否打断别的中断 |
| **IRQn** | Interrupt Request Number | 中断请求编号。每个中断源都有一个编号，CPU 通过编号找到对应的中断处理函数 |

### 0.2 外设相关

| 名词 | 全称 | 通俗解释 |
|------|------|----------|
| **外设 (Peripheral)** | — | 芯片内部集成的各种功能模块的总称。定时器、ADC、串口、SPI、DMA 等都叫"外设"。它们在芯片内部，通过寄存器配置后工作 |
| **TIM (Timer)** | — | 定时器。本质是一个自动计数的计数器，可以定时产生中断、输出 PWM 波、捕获外部脉冲等 |
| **PWM** | Pulse Width Modulation | 脉冲宽度调制。通过改变方波中"高电平占比"（占空比）来控制电机转速、LED 亮度等。比如占空比 50% = 一半时间高电平、一半时间低电平 |
| **占空比 (Duty Cycle)** | — | PWM 波形中，高电平时间占整个周期的比例。0% = 一直低电平，100% = 一直高电平，50% = 一半一半 |
| **CCR (Capture/Compare Register)** | — | 捕获/比较寄存器。在 PWM 模式下，CCR 的值决定了占空比；在输入捕获模式下，CCR 记录捕获时刻的计数值 |
| **ARR (Auto-Reload Register)** | — | 自动重装载寄存器，就是定时器的"周期"。计数器从 0 数到 ARR 就清零重来，这个 ARR 值决定了 PWM 的频率 |
| **PSC (Prescaler)** | — | 预分频器。定时器时钟进来先除以 (PSC+1)，再喂给计数器。比如 PSC=63 就是 64 分频 |
| **ADC** | Analog-to-Digital Converter | 模数转换器。把连续的模拟电压（0~3.3V）转成离散的数字值（0~4095，12位精度） |
| **SPI** | Serial Peripheral Interface | 串行外设接口。一种 3~4 线的高速串行通信协议，常用于驱动屏幕、传感器、LED 等 |
| **USART / UART** | Universal Synchronous/Asynchronous Receiver/Transmitter | 通用同步/异步收发器，就是"串口"。用 TX（发送）和 RX（接收）两根线通信 |
| **DMA** | Direct Memory Access | 直接内存访问。一个不需要 CPU 干预就能自动搬运数据的"搬运工"，CPU 安排好任务后可以去做别的事 |
| **CRC** | Cyclic Redundancy Check | 循环冗余校验。一种数据校验算法，用于检测数据传输是否出错 |
| **SCK / MOSI / MISO / NSS** | SPI 信号线 | SCK=时钟线，MOSI=主出从入（主机发数据），MISO=主入从出（主机收数据），NSS=片选（选中从设备） |
| **TX / RX** | Transmit / Receive | 串口的发送线和接收线。TX 发数据，RX 收数据。通信时双方的 TX-RX 交叉连接 |
| **Baud Rate (波特率)** | — | 串口通信的速度，单位 bps（比特/秒）。115200 = 每秒传 115200 个比特。收发双方必须设置一样的波特率才能通信 |

### 0.3 HAL 库与编程相关

| 名词 | 全称 | 通俗解释 |
|------|------|----------|
| **HAL** | Hardware Abstraction Layer | 硬件抽象层。ST 官方提供的函数库，把底层寄存器操作封装成易读的 C 函数。比如 `HAL_GPIO_WritePin()` 代替直接操作寄存器 |
| **Handle (句柄)** | — | 一个结构体变量，里面存着某个外设的全部配置信息。比如 `htim2` 是 TIM2 的句柄，`huart1` 是 USART1 的句柄。HAL 库所有操作都通过句柄进行 |
| **MSP** | MCU Support Package | HAL 库的底层初始化回调函数。当你调用 `HAL_TIM_Init()` 时，HAL 库会回调 `HAL_TIM_MspInit()` 来做底层（时钟使能、引脚配置等）初始化 |
| **Callback (回调函数)** | — | 一种"你先注册、系统到时机自动调用"的函数。比如 `HAL_TIM_PeriodElapsedCallback` 就是定时器溢出时 HAL 库自动调用的函数，你在里面写自己的逻辑 |
| **USER CODE BEGIN / END** | — | CubeMX 生成的代码中的特殊注释标记。标记之间的代码是用户手写的，CubeMX 重新生成代码时会保留；标记之外的代码会被覆盖 |
| **volatile** | — | C 语言关键字。告诉编译器"这个变量可能被中断或其他途径修改，不要优化它，每次都从内存重新读取"。在中断和主循环共享的变量上必须加 |
| **extern** | — | C 语言关键字。表示"这个变量在别的 .c 文件里定义了，这里只是声明引用"。用于跨文件共享全局变量 |
| **static** | — | C 语言关键字。修饰函数或变量时表示"只在本文件内可见"，其他文件访问不到。用于模块封装 |
| **宏 (#define)** | — | C 预处理指令。定义一个文本替换规则，比如 `#define LED1_Pin GPIO_PIN_2` 编译时会把所有 `LED1_Pin` 替换成 `GPIO_PIN_2` |

### 0.4 时钟相关

| 名词 | 全称 | 通俗解释 |
|------|------|----------|
| **HSI** | High Speed Internal | 内部高速 RC 振荡器，频率 8MHz。不需要外部晶振，精度较低（±1%），但省元件 |
| **HSE** | High Speed External | 外部高速晶振，通常接 8MHz 晶振。精度高，但需要外部元件 |
| **LSE / LSI** | Low Speed External/Internal | 低速时钟，32.768kHz 晶振(外部) 或 ~40kHz RC(内部)。主要用于 RTC 实时时钟和看门狗 |
| **PLL** | Phase Locked Loop | 锁相环，本质是"倍频器"。把输入频率乘以一个倍数输出，比如 4MHz × 16 = 64MHz |
| **SYSCLK** | System Clock | 系统时钟，喂给 CPU 内核的时钟。本项目的 SYSCLK = 64MHz，即 CPU 每秒执行 6400 万条指令 |
| **AHB** | Advanced High-performance Bus | 高速总线，连接 CPU 与内存、DMA、GPIO 等高速模块。AHB 的时钟叫 **HCLK**，通常等于 SYSCLK |
| **HCLK** | AHB Bus Clock | AHB 总线时钟。CPU 跑多快、DMA 跑多快、GPIO 翻转多快都由它决定。本项目 = 64MHz |
| **APB1 / APB2** | Advanced Peripheral Bus 1/2 | 两条外设总线，速度不同。**APB1 是低速总线**（最大 36MHz，挂 TIM2~4, USART2~3, I2C, SPI2）；**APB2 是高速总线**（最大 72MHz，挂 TIM1, USART1, SPI1, ADC, GPIO）。APB1 时钟叫 PCLK1，APB2 时钟叫 PCLK2 |
| **PCLK1 / PCLK2** | Peripheral Clock 1/2 | APB1/APB2 的时钟。本项目 PCLK1 = 32MHz（64÷2），PCLK2 = 64MHz（不分频）。**特殊规则**：当 APB 分频≠1 时，挂在 APB 上的定时器时钟会自动 ×2，所以 TIM2~4 的时钟 = 32×2 = 64MHz |
| **RCC** | Reset and Clock Control | 复位和时钟控制模块。所有时钟的开关、分频、倍频都在这里配置。代码里所有 `__HAL_RCC_xxx_CLK_ENABLE()` 都是让 RCC 打开某个外设的时钟 |
| **FLASH_LATENCY** | — | Flash 等待周期。CPU 跑得太快时 Flash 读不过来，需要插入等待周期。F103 在 48~72MHz 时需要 2 个等待周期（LATENCY_2） |
| **SystemCoreClock** | — | 一个全局变量，存着当前 SYSCLK 的值（单位 Hz），比如 64000000。代码中 `HAL_SYSTICK_Config(SystemCoreClock / 1000)` 就是拿它来算 1ms 的计数值 |

#### 0.4.1 时钟配置宏详解（代码里反复出现的）

> 在 [main.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/main.c) 的 `SystemClock_Config()` 里会看到大量 `RCC_xxx` 开头的宏，下面逐一解释：

| 宏 | 含义 |
|----|------|
| `RCC_OSCILLATORTYPE_HSI` | 选择振荡器类型为 HSI（内部 8MHz）。可选 HSI/HSE/LSI/LSE |
| `RCC_HSI_ON` | 打开 HSI。对应的还有 `RCC_HSI_OFF` |
| `RCC_HSICALIBRATION_DEFAULT` | HSI 校准值用默认值。HSI 精度差，ST 出厂时校准过 |
| `RCC_PLL_ON` | 打开 PLL（倍频器）。要先有源时钟再开 PLL |
| `RCC_PLLSOURCE_HSI_DIV2` | PLL 的输入源 = HSI÷2（8÷2=4MHz）。可选 `HSI_DIV2` 或 `HSE`（外部晶振直连） |
| `RCC_PLL_MUL16` | PLL 倍频 ×16。4MHz×16 = 64MHz。可选 MUL2~MUL16 |
| `RCC_CLOCKTYPE_HCLK` | 要配置 HCLK（AHB 总线时钟） |
| `RCC_CLOCKTYPE_SYSCLK` | 要配置 SYSCLK（系统时钟源选择） |
| `RCC_CLOCKTYPE_PCLK1` | 要配置 PCLK1（APB1 总线时钟） |
| `RCC_CLOCKTYPE_PCLK2` | 要配置 PCLK2（APB2 总线时钟） |
| `RCC_SYSCLKSOURCE_PLLCLK` | SYSCLK 来源 = PLL 输出（64MHz）。可选 HSI(8M)/HSE(8M)/PLL |
| `RCC_SYSCLK_DIV1` | AHB 分频 = 1（不分频），HCLK = SYSCLK = 64MHz。DIV2 = 一半，依此类推 |
| `RCC_HCLK_DIV2` | APB1 分频 = 2，PCLK1 = HCLK÷2 = 32MHz。**APB1 必须分频**，因为它最大只能 36MHz |
| `RCC_HCLK_DIV1` | APB2 分频 = 1（不分频），PCLK2 = 64MHz。APB2 最大可到 72MHz |
| `RCC_PERIPHCLK_ADC` | 要配置 ADC 外设时钟 |
| `RCC_ADCPCLK2_DIV6` | ADC 时钟 = PCLK2÷6 = 64÷6 ≈ 10.67MHz。ADC 最大 14MHz |
| `FLASH_LATENCY_2` | Flash 等待 2 周期。64MHz 下必须设为 2 |
| `__HAL_RCC_GPIOx_CLK_ENABLE()` | 使能 GPIOA/B/C 的时钟。**任何外设使用前必须先开时钟**，否则引脚不工作 |
| `__HAL_RCC_TIMx_CLK_ENABLE()` | 使能定时器时钟。同理还有 `__HAL_RCC_USARTx_CLK_ENABLE()`、`__HAL_RCC_SPIx_CLK_ENABLE()` 等 |
| `__HAL_RCC_DMA1_CLK_ENABLE()` | 使能 DMA1 控制器时钟 |
| `__HAL_RCC_AFIO_CLK_ENABLE()` | 使能 AFIO（复用功能 I/O）模块。需要引脚重映射时必须先开这个时钟 |
| `__HAL_AFIO_REMAP_SWJ_NOJTAG()` | 禁用 JTAG 调试口（释放 PA15/PB3/PB4），保留 SWD（PA13/PA14）。让释放的引脚可以做 GPIO |
| `__HAL_AFIO_REMAP_SPI1_ENABLE()` | 把 SPI1 的引脚从默认的 PA5/PA7 重映射到 PB3/PB5 |

### 0.5 数据格式相关

| 名词 | 全称 | 通俗解释 |
|------|------|----------|
| **MSB / LSB** | Most/Least Significant Bit | 最高有效位 / 最低有效位。比如二进制 `1010`，MSB 在左（1），LSB 在右（0）。SPI 通信可以选先发 MSB 或 LSB |
| **uint8_t / uint16_t / uint32_t** | Unsigned Integer 8/16/32-bit | 无符号整数：8 位(0~255)、16 位(0~65535)、32 位(0~42亿)。带 `int` 的为有符号 |
| **int64_t** | Signed Integer 64-bit | 64 位有符号整数，范围 -922京~+922京。本项目用于脉冲计数器 |
| **float** | Floating Point | 32 位浮点数（带小数点）。STM32F103C8T6 没有硬件浮点单元，浮点运算靠软件模拟，较慢 |
| **Hex (十六进制)** | Hexadecimal | 用 0~9 和 A~F 表示 16 种值的数制。代码里 `0x6c` 就是十六进制的 108。一个十六进制位 = 4 个二进制位 |
| **Byte (字节)** | — | 8 个二进制位（bit）。1 Byte = 8 bit。STM32 中 `uint8_t` 就是 1 字节 |

### 0.6 本项目专用缩写

| 名词 | 解释 |
|------|------|
| **MX_xxx_Init()** | CubeMX 自动生成的外设初始化函数，比如 `MX_GPIO_Init()` 初始化 GPIO，`MX_TIM2_Init()` 初始化 TIM2 |
| **Error_Handler()** | 错误处理函数。如果外设初始化失败就调用它，里面是 `__disable_irq(); while(1){}`，即关中断+死循环。表示系统挂了 |
| **HAL_Delay(ms)** | HAL 库的毫秒级延时函数。`HAL_Delay(1000)` 延时 1 秒。底层依赖 SysTick 中断，所以中断被关了就不能用 |
| **timeTick** | 本项目自定义的全局变量，每 1ms 由 SysTick 中断 +1。用于任务调度的时间基准 |
| **task1ms / task10ms / ...** | 本项目自定义的周期任务函数，在主循环中按时间片调度执行 |

### 0.7 代码中常见的外设配置宏速查

#### GPIO 配置宏（[gpio.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/gpio.c) 中出现）

| 宏 | 含义 |
|----|------|
| `GPIO_MODE_OUTPUT_PP` | 推挽输出模式。引脚能主动输出高/低电平，用于驱动 LED、继电器、电机方向等 |
| `GPIO_MODE_INPUT` | 浮空输入模式。引脚电平由外部决定，用于读取传感器、按键等 |
| `GPIO_MODE_ANALOG` | 模拟模式。引脚交给 ADC 用，不做数字 IO |
| `GPIO_MODE_AF_PP` | 复用推挽输出。引脚交给定时器/串口/SPI 等外设控制输出，不由你手动写 |
| `GPIO_MODE_IT_RISING` | 上升沿触发外部中断。电平从低→高跳变时触发中断 |
| `GPIO_MODE_IT_FALLING` | 下降沿触发外部中断。高→低 |
| `GPIO_MODE_IT_RISING_FALLING` | 双边沿触发。任意跳变都触发 |
| `GPIO_NOPULL` | 不使用内部上拉/下拉电阻。引脚电平完全由外部决定 |
| `GPIO_PULLUP` | 启用内部上拉电阻。悬空时默认高电平 |
| `GPIO_PULLDOWN` | 启用内部下拉电阻。悬空时默认低电平 |
| `GPIO_SPEED_FREQ_LOW` | 低速（2MHz）。用于普通信号，省功耗 |
| `GPIO_SPEED_FREQ_HIGH` | 高速（50MHz）。用于 PWM、SPI 等高速信号 |
| `GPIO_SPEED_FREQ_MEDIUM` | 中速（10MHz） |
| `GPIO_PIN_SET` | 高电平（输出 3.3V）。在 `HAL_GPIO_WritePin` 中使用 |
| `GPIO_PIN_RESET` | 低电平（输出 0V）。在 `HAL_GPIO_WritePin` 中使用 |
| `GPIO_PIN_0` ~ `GPIO_PIN_15` | 引脚编号。可以按位或：`GPIO_PIN_0 \| GPIO_PIN_1` = 同时配置 PA0 和 PA1 |

#### 定时器配置宏（[tim.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/tim.c) 中出现）

| 宏 | 含义 |
|----|------|
| `TIM_COUNTERMODE_UP` | 向上计数。计数器从 0 数到 Period 再清零 |
| `TIM_COUNTERMODE_DOWN` | 向下计数。从 Period 数到 0 |
| `TIM_COUNTERMODE_CENTERALIGNED1/2/3` | 中心对齐模式。0→Period→0 来回数，PWM 更对称 |
| `TIM_CLOCKDIVISION_DIV1` | 定时器内部时钟不分频 |
| `TIM_AUTORELOAD_PRELOAD_ENABLE` | 允许在运行中修改 ARR（周期值）并立即生效。不改 ARR 时用 DISABLE |
| `TIM_AUTORELOAD_PRELOAD_DISABLE` | 不允许运行中修改 ARR（写新值要等下个周期才生效） |
| `TIM_CLOCKSOURCE_INTERNAL` | 时钟来自芯片内部总线（默认），不是外部引脚 |
| `TIM_OCMODE_PWM1` | PWM 模式 1：计数值 < CCR 时输出高电平，否则低电平（常用） |
| `TIM_OCMODE_PWM2` | PWM 模式 2：和 PWM1 反过来，高/低电平对调 |
| `TIM_OCPOLARITY_HIGH` | PWM 有效电平为高电平。即占空比越大 → 高电平时间越长 |
| `TIM_OCPOLARITY_LOW` | PWM 有效电平为低电平。占空比越大 → 低电平时间越长 |

### 1.3 核心概念：什么是 HAL 库？

STM32 的编程有三种层次：

```
你的应用代码 (main.c, app/*.c)
       ↓ 调用
HAL 库 (stm32f1xx_hal_xxx.c)     ← 本项目使用这一层
       ↓ 操作
寄存器 ( stm32f103xb.h 定义)
       ↓ 控制
硬件 (STM32F103C8T6 芯片)
```

**HAL（Hardware Abstraction Layer，硬件抽象层）** 就是 ST 官方提供的"中间函数库"。比如你想让 PA5 输出高电平：

- **直接操作寄存器**：`GPIOA->BSRR = GPIO_PIN_5;`（底层、高效、难懂）
- **用 HAL 库**：`HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);`（可读性强）

本项目全程使用 HAL 库，对初学者更友好。

## 3. 时钟系统配置

### 3.1 什么是时钟？为什么重要？

STM32 芯片内部有很多模块（CPU、GPIO、定时器、ADC、串口...），每个模块都需要时钟信号才能工作。就像人的心跳一样，时钟就是芯片的"心跳脉冲"，决定了各模块运行的速度。

### 3.2 本项目的时钟配置

时钟配置在 [main.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/main.c) 的 `SystemClock_Config()` 函数中：

```
内部高速时钟 HSI (8MHz)
        │
        ├──→ /2 分频 ──→ 4MHz
        │                    │
        │                    └──→ PLL 倍频 ×16 ──→ 64MHz
        │                                          │
        │                                          ├──→ SYSCLK (系统时钟) = 64MHz
        │                                          │
        │                                          ├──→ HCLK (AHB总线) = 64MHz
        │                                          │      │
        │                                          │      ├──→ APB1总线 = 32MHz (HCLK/2)
        │                                          │      │      │
        │                                          │      │      ├──→ TIM2/3/4 定时器时钟 = 64MHz (APB1×2)
        │                                          │      │      ├──→ USART3 时钟 = 32MHz
        │                                          │      │      └──→ DMA1 时钟
        │                                          │      │
        │                                          │      └──→ APB2总线 = 64MHz (HCLK/1)
        │                                          │             │
        │                                          │             ├──→ TIM1 定时器时钟 = 64MHz
        │                                          │             ├──→ USART1 时钟 = 64MHz
        │                                          │             ├──→ SPI1 时钟 = 64MHz
        │                                          │             ├──→ ADC1 时钟 = 10.67MHz (APB2/6)
        │                                          │             └──→ GPIO 时钟
```

### 3.3 关键代码解读

```c
// 使用内部 RC 振荡器（HSI），不使用外部晶振
RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSI;
RCC_OscInitStruct.HSIState = RCC_HSI_ON;

// PLL 配置：HSI 先除以 2（8/2=4MHz），再乘以 16（4×16=64MHz）
RCC_OscInitStruct.PLL.PLLSource = RCC_PLLSOURCE_HSI_DIV2;
RCC_OscInitStruct.PLL.PLLMUL = RCC_PLL_MUL16;

// APB1 分频 = 2，所以 APB1 = 64/2 = 32MHz
RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV2;

// APB2 不分频，所以 APB2 = 64MHz
RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV1;

// ADC 时钟 = APB2(64MHz) / 6 ≈ 10.67MHz
PeriphClkInit.AdcClockSelection = RCC_ADCPCLK2_DIV6;
```

> **小白知识点**：STM32F103 的 APB1 定时器时钟有一个特殊规则——当 APB1 分频不为 1 时，定时器时钟会自动 ×2。所以 APB1=32MHz，但 TIM2/3/4 的时钟是 64MHz。

### 3.4 SysTick（系统滴答定时器）

```c
// 在 main() 中配置：
HAL_SYSTICK_Config(SystemCoreClock / 1000);  // 64MHz/1000 = 64KHz → 1ms 中断一次
HAL_NVIC_SetPriority(SysTick_IRQn, 0, 0);   // 最高优先级
```

SysTick 是 Cortex-M3 内核自带的 24 位递减计数器。这里配置为 **每 1ms 产生一次中断**，用于：

1. `HAL_IncTick()` — HAL 库内部计时（`HAL_Delay()` 依赖此）
2. `timeTick++` — 用户自定义的时间计数器（用于任务调度）

## 4. GPIO（引脚）配置详解

### 4.1 什么是 GPIO？

GPIO（General Purpose Input/Output，通用输入输出）就是芯片上可以输入或输出电信号的引脚。每个引脚可以配置为：

| 模式 | 说明 | 本项目用途 |
|------|------|-----------|
| `GPIO_MODE_OUTPUT_PP` | 推挽输出 | 控制继电器、LED、电机方向等 |
| `GPIO_MODE_INPUT` | 浮空输入 | 读取按键、传感器信号 |
| `GPIO_MODE_IT_RISING` | 上升沿触发中断 | 检测外部脉冲信号 |
| `GPIO_MODE_ANALOG` | 模拟模式 | ADC 采样 |
| `GPIO_MODE_AF_PP` | 复用推挽输出 | 定时器PWM、串口TX、SPI等 |

### 4.2 GPIO 初始化流程

GPIO 配置在 [gpio.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/gpio.c) 的 `MX_GPIO_Init()` 函数中：

```c
void MX_GPIO_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    // 第1步：使能 GPIO 端口时钟（必须！否则 GPIO 不工作）
    __HAL_RCC_GPIOC_CLK_ENABLE();
    __HAL_RCC_GPIOA_CLK_ENABLE();
    __HAL_RCC_GPIOB_CLK_ENABLE();

    // 第2步：设置初始电平（上电时的默认输出状态）
    HAL_GPIO_WritePin(GPIOA, Servo_Pin|stepMoter1Rst_Pin, GPIO_PIN_SET);  // 高电平
    HAL_GPIO_WritePin(GPIOA, GPIO_PIN_3, GPIO_PIN_RESET);                  // 低电平
    HAL_GPIO_WritePin(GPIOB, waterPumpIo_Pin|LED1_Pin|..., GPIO_PIN_SET);  // 高电平

    // 第3步：逐个配置引脚的模式
    // ...（见下方详解）
}
```

### 4.3 GPIO 配置详解

#### 4.3.1 外部中断输入引脚（EXTI）

```c
// PC13 - 清水滤网检测 / PC15 - 电源检测
GPIO_InitStruct.Pin = clearWaterFT_Pin|power_Pin;       // PC13, PC15
GPIO_InitStruct.Mode = GPIO_MODE_IT_RISING;               // 上升沿触发中断
GPIO_InitStruct.Pull = GPIO_NOPULL;                       // 不上拉不下拉
HAL_GPIO_Init(GPIOC, &GPIO_InitStruct);

// 使能 EXTI15_10 中断，优先级 6（较低）
HAL_NVIC_SetPriority(EXTI15_10_IRQn, 6, 0);
HAL_NVIC_EnableIRQ(EXTI15_10_IRQn);
```

**效果**：当 PC13 或 PC15 上出现低→高的电平跳变时，触发 `EXTI15_10_IRQHandler()` 中断。

#### 4.3.2 普通输入引脚

```c
// PC14 - 盒子在位检测

GPIO_InitStruct.Mode = GPIO_MODE_INPUT;     // 纯输入模式
GPIO_InitStruct.Pull = GPIO_NOPULL;
HAL_GPIO_Init(boxAvail_GPIO_Port, &GPIO_InitStruct);
```

**效果**：可以随时用 `HAL_GPIO_ReadPin(boxAvail_GPIO_Port, boxAvail_Pin)` 读取电平。

#### 4.3.3 推挽输出引脚（控制外设开关）

这是本项目用得最多的模式。推挽输出能主动输出高电平（3.3V）或低电平（0V）。

```c

GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;          // 推挽输出
GPIO_InitStruct.Pull = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_HIGH;        // 高速（50MHz）
HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

// PB1/PB2/PB12/PB13/PB14/PB15/PB4/PB6/PB7/PB9 - 各种泵和开关控制

                      |tmux1308A0_Pin|beep_Pin|drinePumpA_Pin|drinePumpB_Pin
                      |hosePumpIo_Pin;

GPIO_InitStruct.Pull = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_HIGH;
HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
```

**效果**：通过 `HAL_GPIO_WritePin(端口, 引脚, 状态)` 控制外设的开关。例如：

```c
HAL_GPIO_WritePin(beep_GPIO_Port, beep_Pin, 0);    // 蜂鸣器关

```

#### 4.3.4 多路复用器控制引脚

```c
// PB14/PB13/PB12 - TMUX1308 地址选择 A0/A1/A2
// 通过 3 位二进制编码选择 8 路通道（000~111）

GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
```

## 5. 定时器（TIM）配置详解

### 5.1 什么是定时器？

定时器是 STM32 中最重要的外设之一。它本质上是一个**自动计数的计数器**，可以：

- **定时**：周期性产生中断（如每 1ms 中断一次）
- **PWM 输出**：产生可调占空比的方波（控制电机转速、LED亮度等）
- **输入捕获**：测量外部脉冲的频率/脉宽（如编码器测速）
- **输出比较**：在特定计数值时改变输出电平

### 5.2 本项目使用了 4 个定时器

| 定时器 | 用途 | 中断优先级 |
|--------|------|-----------|
| TIM1 | 输入捕获 — 脉冲编码器测速 | 7（最低） |
| TIM2 | PWM 输出 — 28步进电机（开关阀） | 4 |
| TIM3 | PWM 输出 — 57步进电机微步进 + 清水泵PWM | 5 |
| TIM4 | PWM 输出 — 蠕动泵PWM + 定时中断 — 舵机控制 | 3 |

### 5.3 TIM1 — 输入捕获（脉冲编码器测速）

#### 配置（[tim.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/tim.c)）

```c

htim1.Init.CounterMode = TIM_COUNTERMODE_UP;  // 向上计数

```

#### 引脚

```

PA11 → 方向判断（高=正转，低=反转）
```

```c
}

// 每捕获到一个脉冲，触发中断：
void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM1) {
        if (htim->Channel == HAL_TIM_ACTIVE_CHANNEL_1) {
            // 读 PA11 判断方向

                pulseCount++;   // 正转
            else
                pulseCount--;   // 反转
        }
    }
```

```c
    // 使用 64 点正弦表平滑控制电流
    switch(uln2803Index) {
        case 0: TIM2->CCR1 = sinTable[moter28Index]; TIM2->CCR2 = 0; break;
        case 1: TIM2->CCR1 = 3199; TIM2->CCR2 = sinTable[moter28Index]; break;
        case 2: TIM2->CCR1 = sinTable[63-moter28Index]; TIM2->CCR2 = 3199; break;
        case 3: TIM2->CCR1 = 0; TIM2->CCR2 = sinTable[63-moter28Index]; break;
    }
    // 正转或反转
    if (dir == 0) {
        moter28Index = (moter28Index + 1) % 64;  // 正转一步
    } else {
        moter28Index = (moter28Index == 0) ? 63 : moter28Index - 1;  // 反转一步
    }
}
```

#### 57步进电机微步进控制（[StepperPulse57_8412.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/app/StepperPulse57_8412.c)）

这是本项目最复杂的驱动，原理如下：

```
传统步进电机驱动：通/断电让电机跳一步（粗糙、噪音大）
微步进驱动：用 PWM 模拟正弦波电流，让电机平滑移动（精细、静音）

TIM3 的 PWM 中心值 = 1600（50%占空比 = 零电流）
正弦波峰值 = 3199（100%占空比 = 正向满电流）
正弦波谷值 = 0（0%占空比 = 反向满电流）

256 点正弦表 → 电机一圈 = 256 微步 × 50 减速比 = 12800 步
```

每次 TIM3 溢出中断时，`StepperPulse57_Tick()` 被调用：

```c
void StepperPulse57_Tick(void) {
    // 1. 分频控制：每 SpeedDivider 次中断才推进一步（控制转速）
    if (++StepperPWM_Divider < StepperPWM_SpeedDivider) {
        // 即使没推进一步，也刷新 PWM 保持电流连续
        idx = StepperPWM_Index;
        valA = SineTable256[idx];
        valB = SineTable256[(idx + 64) % 256];  // 相位差 90°
        // 按幅值缩放
        valA = 1600 + (valA - 1600) * Amplitude / 100;
        valB = 1600 + (valB - 1600) * Amplitude / 100;
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, valA);
        __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_2, valB);
        return;
    }
    StepperPWM_Divider = 0;

    // 2. 分数步进推进
    StepperPWM_StepAccum += StepperPWM_StepRate;
    while (StepperPWM_StepAccum >= 64) {
        StepperPWM_StepAccum -= 64;
        if (Direction >= 0)
            StepperPWM_Index = (StepperPWM_Index + 1) & 0xFF;  // 正转
        else
            StepperPWM_Index = (StepperPWM_Index - 1) & 0xFF;  // 反转
    }

    // 3. 更新 PWM 输出
    idx = StepperPWM_Index;
    valA = SineTable256[idx];                          // sin(θ)
    valB = SineTable256[(idx + 64) % 256];             // cos(θ) = sin(θ+90°)
    __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, valA);
    __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_2, valB);
}
```

**转速公式**：`RPM = 3000 × StepRate / (2048 × Divider)`

舵机（SG90 类）的控制原理：

- 高电平时间 0.5ms~2.5ms 对应 0°~180°

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM4) {
        servoCnt++;
        // servoCnt 在 0~199 之间循环（200×0.1ms = 20ms 周期 = 50Hz）

        if (servoCnt < 200 && servoCnt > servoDesCnt) {
            // 输出低电平（PWM 有效部分）
            HAL_GPIO_WritePin(Servo_GPIO_Port, Servo_Pin, GPIO_PIN_RESET);
        }
        if (servoCnt > 199) {
            // 输出高电平（PWM 无效部分），开始新周期
            HAL_GPIO_WritePin(Servo_GPIO_Port, Servo_Pin, GPIO_PIN_SET);
            servoCnt = 0;
        }
    }
}
```


## 6. ADC（模数转换）配置详解

### 6.1 什么是 ADC？

ADC（An-to-Digital Converter，模数转换器）将模拟电压信号转换为数字值。STM32F103C8T6 的 ADC 是 12 位精度，量程 0~3.3V，转换结果 0~4095。

```
0V    → ADC值 = 0
1.65V → ADC值 = 2048
3.3V  → ADC值 = 4095
```

### 6.2 本项目 ADC 配置（[adc.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/adc.c)）

本项目巧妙地使用了 ADC 的**两个通道**：常规通道和注入通道。

```c
hadc1.Instance = ADC1;
hadc1.Init.ScanConvMode = ADC_SCAN_DISABLE;             // 非扫描模式
hadc1.Init.ContinuousConvMode = DISABLE;                 // 单次转换
hadc1.Init.ExternalTrigConv = ADC_SOFTWARE_START;        // 软件触发
hadc1.Init.DataAlign = ADC_DATAALIGN_RIGHT;              // 数据右对齐（12位在低12位）
hadc1.Init.NbrOfConversion = 1;                          // 1个常规转换

// 常规通道：ADC_CHANNEL_4 (PA4) — 总线电流检测
sConfig.Channel = ADC_CHANNEL_4;
sConfig.Rank = ADC_REGULAR_RANK_1;
sConfig.SamplingTime = ADC_SAMPLETIME_239CYCLES_5;       // 采样时间 239.5 周期
// 转换时间 = (239.5 + 12.5) / 10.67MHz ≈ 23.6μs（较慢但更精准）

// 注入通道：ADC_CHANNEL_5 (PA5) — TMUX1308 模拟量
sConfigInjected.InjectedChannel = ADC_CHANNEL_5;
sConfigInjected.InjectedRank = ADC_INJECTED_RANK_1;
sConfigInjected.InjectedSamplingTime = ADC_SAMPLETIME_239CYCLES_5;
sConfigInjected.ExternalTrigInjecConv = ADC_INJECTED_SOFTWARE_START;
```

#### 引脚

```
PA4 → ADC1_IN4 → 总线电流检测（板载直连）
PA5 → ADC1_IN5 → TMUX1308 模拟量输出（多路复用后的信号）
```

#### 为什么要两个通道？

- **常规通道（PA4）**：直接读取板载电流传感器，不需要切换
- **注入通道（PA5）**：通过 TMUX1308 多路复用器扩展，一次只能读一路，需要切换通道后读取

> **小白知识点 — 注入通道**：STM32 的 ADC 注入通道可以在常规转换进行时"插队"转换，优先级更高。这里利用两个独立通道，分别读取不同的模拟量。

### 6.3 采样使用方式（[tmux1308.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/app/tmux1308.c)）

```c

    HAL_ADC_Start(&hadc1);                          // 启动 ADC

    *value = (uint16_t)HAL_ADC_GetValue(&hadc1);     // 读取结果
    HAL_ADC_Stop(&hadc1);                             // 停止
    return HAL_OK;
}

    HAL_ADCEx_InjectedStart(&hadc1);                 // 启动注入通道
    HAL_ADCEx_InjectedPollForConversion(&hadc1, 10); // 等待转换
    *value = HAL_ADCEx_InjectedGetValue(&hadc1, ADC_INJECTED_RANK_1);
    HAL_ADCEx_InjectedStop(&hadc1);
    return HAL_OK;
}
```

## 7. SPI 配置详解

### 7.1 什么是 SPI？

SPI（Serial Peripheral Interface，串行外设接口）是一种高速同步串行通信协议，用于芯片与外设之间短距离通信。需要 3~4 根线：

| 信号线 | 说明 |
|--------|------|
| SCK | 时钟线（主设备产生） |
| MOSI | 主设备输出，从设备输入 |
| MISO | 主设备输入，从设备输出 |
| CS/SS | 片选信号（选择从设备） |

### 7.2 本项目 SPI 配置（[spi.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/spi.c)）

```c
hspi1.Instance = SPI1;
hspi1.Init.Mode = SPI_MODE_MASTER;                    // SPI 主机模式
hspi1.Init.Direction = SPI_DIRECTION_2LINES;          // 双线传输
hspi1.Init.DataSize = SPI_DATASIZE_8BIT;              // 8 位数据帧
hspi1.Init.CLKPolarity = SPI_POLARITY_LOW;            // 空闲时 SCK 为低电平
hspi1.Init.CLKPhase = SPI_PHASE_1EDGE;                // 第一个边沿采样（SPI Mode 0）
hspi1.Init.NSS = SPI_NSS_SOFT;                        // 软件控制片选
hspi1.Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_32;  // 时钟 32 分频
// SPI 时钟 = 64MHz / 32 = 2MHz
hspi1.Init.FirstBit = SPI_FIRSTBIT_MSB;               // 高位先传
hspi1.Init.CRCCalculation = SPI_CRCCALCULATION_DISABLE;  // 不使用硬件 CRC
```

#### 引脚

```
PB3 → SPI1_SCK  （时钟输出）
PB5 → SPI1_MOSI （数据输出）
```

> **注意**：SPI1 默认引脚是 PA5/PA7，这里通过 `__HAL_AFIO_REMAP_SPI1_ENABLE()` 重映射到 PB3/PB5。

### 7.3 SPI 的用途 — 驱动 WS2812 LED 灯带

这是一个非常巧妙的设计！WS2812 需要精确的时序信号（0.3μs/0.9μs），而用 SPI 可以完美模拟：

#### WS2812 时序要求

```
WS2812 逻辑 0：高电平 0.3μs + 低电平 0.9μs（总计 1.2μs）
WS2812 逻辑 1：高电平 0.6μs + 低电平 0.6μs（总计 1.2μs）
```

#### SPI 编码方案（[ws2812.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/app/ws2812.c)）

SPI 时钟 = 2MHz → 每个位 0.5μs → 3 个 SPI 位 = 1.5μs（接近 WS2812 的 1.2μs）

```
WS2812 逻辑 0 → SPI 发送 100（高 0.5μs + 低 1.0μs）
WS2812 逻辑 1 → SPI 发送 110（高 1.0μs + 低 0.5μs）
```

一颗灯 24 位（GRB）→ 编码成 72 个 SPI 位 = 9 字节

```c
static void WS2812_EncodeByte(uint8_t data, uint8_t *output) {
    uint32_t encoded = 0;
    for (uint8_t i = 0; i < 8; i++) {
        encoded <<= 3;
        if ((data & 0x80U) != 0U) {
            encoded |= 0x06U;   // 110 = WS2812 逻辑 1
        } else {
            encoded |= 0x04U;   // 100 = WS2812 逻辑 0
        }
        data <<= 1;
    }
    output[0] = (uint8_t)(encoded >> 16);
    output[1] = (uint8_t)(encoded >> 8);
    output[2] = (uint8_t)encoded;
}
```

#### PB3 引脚复用

PB3 引脚有双重用途，通过软件切换：

```c
// 切换为 SPI 模式（驱动 LED）
static void Ws2812EnterSpiMode(void) {
    GPIO_InitStruct.Pin = GPIO_PIN_3;
    GPIO_InitStruct.Mode = GPIO_MODE_AF_PP;        // 复用推挽（SPI SCK）
    HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
}

// 切换回 GPIO 中断模式
static void Ws2812ExitSpiMode(void) {
    GPIO_InitStruct.Pin = GPIO_PIN_3;
    GPIO_InitStruct.Mode = GPIO_MODE_IT_RISING;   // 上升沿中断
    GPIO_InitStruct.Pull = GPIO_PULLUP;
    HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
}
```

> **设计思路**：PB3 平时作为外部中断输入使用，当需要更新 LED 颜色时临时切换为 SPI SCK，发送完数据后再切回来。这是一个引脚复用的好例子。

## 9. DMA 配置详解

### 9.1 什么是 DMA？

DMA（Direct Memory Access，直接内存访问）是一种**不需要 CPU 干预**就能在内存和外设之间搬运数据的机制。

```
没有 DMA：
  CPU 发送 1 字节 → 等待 → 发送 1 字节 → 等待 → ...
  （CPU 一直被占用，无法做其他事）

有 DMA：
  CPU： "DMA，帮我把这块内存的数据发到 SPI"
  DMA： "好的，你去忙别的吧"
  DMA： 自动搬运所有数据 → 完成后通知 CPU
```

### 9.2 本项目 DMA 配置（[dma.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/dma.c) + [spi.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/spi.c)）

```c
// DMA 控制器时钟使能

// DMA1 通道 3 用于 SPI1 发送
hdma_spi1_tx.Instance = DMA1_Channel3;
hdma_spi1_tx.Init.Direction = DMA_MEMORY_TO_PERIPH;    // 内存 → 外设
hdma_spi1_tx.Init.PeriphInc = DMA_PINC_DISABLE;         // 外设地址不自增
hdma_spi1_tx.Init.MemInc = DMA_MINC_ENABLE;             // 内存地址自增（逐字节搬运）
hdma_spi1_tx.Init.PeriphDataAlignment = DMA_PDATAALIGN_BYTE;  // 外设数据 8 位
hdma_spi1_tx.Init.MemDataAlignment = DMA_MDATAALIGN_BYTE;     // 内存数据 8 位
hdma_spi1_tx.Init.Mode = DMA_NORMAL;                     // 正常模式（单次传输）
hdma_spi1_tx.Init.Priority = DMA_PRIORITY_LOW;          // 低优先级

// 将 DMA 与 SPI 关联
__HAL_LINKDMA(spiHandle, hdmatx, hdma_spi1_tx);
```

### 9.3 DMA 用于 WS2812 数据传输

## 11. 中断系统详解

### 11.1 什么是中断？

中断是微控制器处理突发事件的核心机制。当特定事件发生时，CPU 暂停当前工作，跳转到**中断服务函数（ISR）**处理事件，处理完后返回原来的位置继续执行。

```
正常执行：A → B → C → D → E
                     ↑
                   中断发生
                     ↓
中断处理：A → B → [中断函数] → C → D → E
```

### 11.2 中断优先级

STM32F103 使用 4 位优先级（NVIC），分为**抢占优先级**和**子优先级**：

- **抢占优先级**：高抢占可以打断低抢占正在执行的中断（嵌套）
- **子优先级**：同抢占级别中，决定谁先响应（不嵌套）

本项目的优先级分配（数字越小优先级越高）：

| 中断源 | 抢占优先级 | 说明 |
|--------|-----------|------|
| SysTick | 0 | 系统滴答（1ms 计时） |
| USART3 | 0 | 高压板通信（最高优先级） |
| DMA1_Channel3 | 0 | SPI DMA 传输完成 |
| TIM4 | 3 | 舵机 PWM 控制 |
| TIM2 | 4 | 28步进电机控制 |
| USART1 | 4 | 上位机通信 |
| TIM3 | 5 | 57步进电机控制 |
| EXTI15_10 | 6 | 外部中断（按键等） |
| TIM1_CC | 7 | 编码器脉冲捕获（最低） |

### 11.3 中断服务函数（[stm32f1xx_it.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/stm32f1xx_it.c)）

## 12. 启动文件与底层

### 12.1 启动文件（startup_stm32f103c8tx.s）

启动文件是用**汇编语言**写的，负责芯片上电后的初始化工作：

```
上电 → 启动文件:
  1. 设置初始堆栈指针（SP 指向 RAM 顶部）
  2. 设置 PC 指针指向 Reset_Handler
  3. Reset_Handler:
     - 将 .data 段从 Flash 复制到 RAM（初始化全局变量）
     - 清零 .bss 段（未初始化的全局变量）
     - 调用 SystemInit() → 配置时钟
     - 调用 __libc_init_array → 初始化 C 库
     - 调用 main() → 进入主程序
```

> **小白理解**：启动文件就是芯片"开机第一个运行的程序"，它负责准备好 C 语言运行环境，然后跳转到 `main()` 函数。**你通常不需要修改它**。

### 12.2 HAL MSP 配置（[stm32f1xx_hal_msp.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/Core/Src/stm32f1xx_hal_msp.c)）

MSP（MCU Support Package）是 HAL 库的底层初始化回调，负责外设的底层硬件配置：

```c
void HAL_MspInit(void) {
    __HAL_RCC_AFIO_CLK_ENABLE();   // 使能 AFIO 时钟（引脚重映射需要）
    __HAL_RCC_PWR_CLK_ENABLE();    // 使能电源管理时钟

    // 禁用 JTAG，保留 SWD 调试
    // 释放 JTAG 占用的 PA15/PB3/PB4 引脚供 GPIO 使用
    __HAL_AFIO_REMAP_SWJ_NOJTAG();
}
```

> **重要**：`__HAL_AFIO_REMAP_SWJ_NOJTAG()` 释放了 JTAG 使用的引脚（PA15、PB3、PB4），使它们可以作为普通 GPIO 使用。这就是为什么 PA15 能控制步进电机复位，PB3 能作为 SPI SCK。

## 13. 任务调度系统

### 13.1 为什么需要任务调度？

STM32 没有操作系统（裸机开发），但项目中有多个任务需要以不同频率执行。本项目使用**时间片轮转调度**：

```
main() 主循环:
  while(1) {
      if (timeTick - task1msTick >= 1)     → task1ms()    每 1ms 执行
      if (timeTick - task10msTick >= 10)   → task10ms()  每 10ms 执行
      if (timeTick - task20msTick >= 20)   → task20ms()  每 20ms 执行
      if (timeTick - task50msTick >= 50)   → task50ms()  每 50ms 执行
      if (timeTick - task200msTick >= 200) → task200ms() 每 200ms 执行
      if (timeTick - task1000msTick >= 1000) → task1000ms() 每 1s 执行
  }
```

### 13.2 各任务职责

| 任务 | 频率 | 职责 |
|------|------|------|
| task1ms() | 1ms | 开关阀到位检测（预留，当前为空） |
| task10ms() | 10ms | 解析上位机命令并执行 |
| task20ms() | 20ms | TMUX1308 数据扫描 + 数据池更新 + 阀门到位检测 + 数据上报 |
| task50ms() | 50ms | 高压板数据重传 |
| task200ms() | 200ms | 温度采集 |
| task1000ms() | 1s | （当前为空，预留扩展） |

### 13.3 调度算法详解

```c
// 1ms 任务独立判断，保证实时性
if (timeTick - task1msTick >= 1) {
    task1msTick = timeTick;
    task1ms();
}

// 其他任务用"最近到期"策略，避免多个任务同时执行
uint32_t minDiff = 0xFFFFFFFF;
uint8_t selectedTask = 0;

// 检查每个任务是否到期，记录到期时间最短的
if (timeTick - task10msTick >= 10)   { minDiff = timeTick - task10msTick; selectedTask = 1; }
if (timeTick - task20msTick >= 20)   { if ((timeTick - task20msTick) < minDiff) { selectedTask = 2; }}
// ...

// 只执行最近到期的那个任务
switch (selectedTask) {
    case 1: task10ms(); break;
    case 2: task20ms(); break;
    // ...
}
```

> **设计思路**：每次循环只执行一个任务，避免任务堆积导致主循环卡死。1ms 任务单独处理，保证最高实时性。

```c
    CMDBRINEPUMPOFF,   // 0x04 点卤泵关
    CMDHOSEPUMPON,     // 0x05 蠕动泵开
    CMDHOSEPUMPOFF,    // 0x06 蠕动泵关
    CMDPUSHMOTORDOWN,  // 0x07 压制电机下压

    CMDPUSHMOTORSTOP,  // 0x09 压制电机停止
    CMDRISEMOTORDOWN,  // 0x0A 抬升电机下压
    CMDRISEMOTORUP,    // 0x0B 抬升电机上升
    CMDRISEMOTORSTOP,  // 0x0C 抬升电机停止
    CMDLIGHTSHOW,      // 0x0D LED 灯光

    CMDVAVLEON,        // 0x0F 阀门开
    CMDVAVLEOFF,       // 0x10 阀门关
    CMDLEDON,          // 0x11 开灯
    CMDLEDOFF,         // 0x12 关灯
    CMD_MAX
} CommandCmd_t;

// 使用宏简化包装函数的编写
#define WRAP_0(F) \
static void wrapper_##F(CommandParam_t *param){ (void)param; F(); }

// 命令查找表（函数指针数组）
static CommandAction_t actionTable[CMD_MAX] = {
    [CMDWATERPUMPON]  = wrapper_waterPumpOn,
    [CMDWATERPUMPOFF] = wrapper_waterPumpOff,
    // ...
};

// 命令执行
void commandExecute(uint8_t command, CommandParam_t *param) {
    if (command == CMDNONE || command >= CMD_MAX) return;
    if (actionTable[command] == NULL) return;
    actionTable[command](param);  // 通过函数指针调用对应函数
}
```

> **设计优点**：添加新命令只需在枚举中加一行、在表中加一行，不需要修改 `commandExecute` 逻辑。这是嵌入式开发中很实用的设计模式。

### 14.4 温度传感器查表（[Tempurature.c](file:///d:/workspace/Code/Keil/zhidou-f103c8t6/code/app/Tempurature.c)）

使用 NTC 热敏电阻测量水温，通过 ADC 采样后查表转换：

```c
// 预校准的 ADC-温度对照表（25℃~98℃，每度一个点）
static const TempTable_t temp_table[] = {
    {3381, 25},  // ADC=3381 → 25℃
    {3280, 30},  // ADC=3280 → 30℃
    {2786, 50},  // ADC=2786 → 50℃
    {1880, 80},  // ADC=1880 → 80℃
    {1535, 98},  // ADC=1535 → 98℃
    // ...
};

// 线性插值计算温度
static float adc_to_temperature(uint16_t adc) {
    // 在两个已知点之间做线性插值
    // 如 ADC=3000，落在 42℃(3000) 和 43℃(2976) 之间
    // 温度 = 42 + (3000-3000)/(2976-3000) × (43-42)
    for (i = 0; i < TEMP_TABLE_SIZE - 1; i++) {
        if (adc <= temp_table[i].adc && adc >= temp_table[i+1].adc) {
            temp = temp_table[i].temp +
                   (float)(adc - temp_table[i].adc) *
                   (temp_table[i+1].temp - temp_table[i].temp) /
                   (float)(temp_table[i+1].adc - temp_table[i].adc);
            return temp;
        }
    }
    return -100.0f;  // 超出范围
}
```

> **为什么用查表而不是公式？** NTC 热敏电阻的阻值-温度关系是非线性的，理论公式（Steinhart-Hart）计算量大。查表+线性插值在嵌入式系统中更高效、更直观。

```c
volatile int64_t pulseCount = 0;  // 全局脉冲计数器

// 初始化：启动 TIM1 输入捕获中断
void pulseTurnsInit(void) {
    HAL_TIM_IC_Start_IT(&htim1, TIM_CHANNEL_1);
}

// 获取圈数（1000 脉冲 = 1 圈）
float pulseTurnsGet(void) {
    return (float)pulseCount / 1000.0f;
}

// 输入捕获回调：每捕获到一个脉冲
void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM1 && htim->Channel == HAL_TIM_ACTIVE_CHANNEL_1) {
        // 读 PA11 判断旋转方向
        if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_11) == GPIO_PIN_RESET)
            pulseCount++;   // 正转
        else
            pulseCount--;   // 反转
    }
}
```

**效果**：通过 TIM1 的输入捕获功能，自动检测外部编码器的每一个脉冲，配合方向引脚判断正反转，最终可读取出精确的圈数（精度 1/1000 圈）。

## 15. 通信协议详解

### 15.1 上位机 → STM32（USART1，115200bps）

帧格式（10 字节）：

```
字节0    字节1~6          字节7~8      字节9
帧头     命令+参数(6字节)   CRC16(2字节)  帧尾
0x??    [cmd][para0~4]    [CRC_L][CRC_H] 0x??
```

接收流程：
1. USART1 中断接收 10 字节
2. 对前 7 字节计算 CRC16
3. CRC 校验通过 → 提取命令字节和参数
4. 在 `task10ms()` 中调用 `commandExecute()` 执行命令

### 15.2 STM32 → 上位机（USART1）

发送流程：
1. `dataPoolUpdate()` 在 `task20ms()` 中更新数据池
2. `dataSync()` 每 20ms 轮询发送一组数据
3. 数据 + CRC16 + 帧尾 → `HAL_UART_Transmit()` 发送

### 15.3 STM32 ↔ 高压板（USART3，9600bps）

```c
// 转发高压广播命令

    highBroadOrder[0] = lowBroadOrder[1];

    }
    if (reTransNum < 0) {
        reTransNum = 3;
        ishighVolData = 0;  // 停止重传
    }
}
```
